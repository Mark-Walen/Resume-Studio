# 安全与隐私

## 1. 身份与授权

- 除健康检查外，业务 API 必须验证 Firebase ID token。
- 未验证邮箱返回 403。
- 数据库查询始终以 token 中的 UID 作为所有权条件。
- 还原点、附件、专栏发布和工作区写入均不能使用客户端提供的 UID。

## 2. API Key

- Key 使用 AES-256-GCM 和随机 IV 加密。
- 不可导出的主密钥保存在 IndexedDB；配置元数据仅保存密文引用。
- 旧明文记录在成功迁移后删除。
- Key 只在模型调用或用户主动查看时短暂解密，不同步至云端。
- 该措施不能抵御已成功执行的同源 XSS，因此 CSP、富文本过滤和依赖治理仍是必要防线。

## 3. 输入与内容安全

- 富文本/Markdown 不执行脚本；链接协议受限。
- 图片只允许安全 HTTP(S) 或经过约束的数据格式。
- 上传文件检查扩展名、MIME、文件头、路径穿越、脚本和提示注入。
- 自定义 AI Base URL 仅允许 HTTPS 公网主机，阻止 localhost、私网和 `.local`。
- 招聘网页代理限制公开 URL，并拦截非必要子资源。

## 4. 隐私最小化

- 最近账户列表只保存 UID、邮箱、昵称和头像 URL，不保存密码、刷新令牌或 ID token。
- 社区专栏发布前剥离阅读笔记、高亮和完成状态。
- 工作历史证据只提取可验证成果；密钥、客户机密、内部项目名需匿名化。

## 5. 已知风险与后续

- 前端自带 Key 的模型调用仍会把 Key 交给同源服务；长期应提供托管凭据或 Secret Manager。
- 工作区目前采用顶层最后写入优先；并发冲突需要版本控制。
- 公开专栏目前要求登录；若开放匿名试读，需要单独的公开读取速率限制和内容审核。
