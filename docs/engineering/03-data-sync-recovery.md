# 数据、同步与恢复设计

## 1. 工作区聚合

工作区快照包含：多份简历与当前简历、职位、面试、诊断、闪卡、知识专栏、求职手记及脱敏后的模型配置。附件仅记录 Cloud Storage 对象信息。

## 2. 保存模式

### 增量更新

前端保存上一份云端快照。每次本地变更后比较顶层数据域，只把变化域通过 `PATCH /api/workspace` 发送。数据库使用 JSONB 顶层合并，因此一次简历编辑不会重复上传未变化的面试或知识库。

### 全量更新

用户可在“云端同步与还原”中执行 `PUT /api/workspace`，用当前完整快照覆盖云端。适用于迁移、故障恢复或一致性校正。

### 首次登录迁移

- 云端存在：云端为准并回写本地。
- 云端不存在且本地有数据：将本地快照迁移到云端。
- 两者均不存在：初始化空白个人工作区，不注入演示数据。

## 3. 还原点

- 还原点是用户主动创建的完整 JSONB 快照。
- 每个用户最多展示最近 30 个还原点。
- 回滚只允许操作当前 UID 的还原点，并整体替换当前工作区。
- 回滚后前端立即应用返回快照并更新本地缓存。

## 4. 冲突策略

当前版本是单写者最后写入优先，增量粒度为顶层数据域。跨设备同时编辑同一数据域可能发生后写覆盖。后续演进应增加：

- 快照版本号或 ETag；
- 条件更新与冲突提示；
- 简历、职位、专栏级别的实体版本；
- 可视化三方合并。

## 5. 故障体验

- 云端失败不阻断本地编辑。
- 错误提示可关闭，保存图标切换为 `CloudOff`。
- 用户可点击重试、执行全量更新或从还原点回滚。
- 本地附件上传失败会保留 IndexedDB 缓存，并在后续登录重试。
